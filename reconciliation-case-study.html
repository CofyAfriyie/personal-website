Reconciliation & exception management

A controlled way to connect records across sources, explain unresolved differences, and keep summary figures tied to transaction-level evidence.

Role: analysis & control designTools: SQL · Power Query · Power BIStatus: interactive prototype (synthetic data)

Try it: a working prototype of this matching sequence runs on invented records. Open the demonstration →

The question

How can a team reconcile two transaction sources without hiding uncertain matches or spending most of its time reviewing records that already agree?

The approach

The workflow preserves each source record, standardizes comparable fields, applies matching rules in a deliberate order, and sends only unresolved records to a review queue.

Exact first

Match unique references before using amount, date, or text similarity.

One rule at a time

Record which rule created each match so a reviewer can reproduce it.

No silent guessing

Keep ambiguous records open rather than forcing the totals to agree.

Calculated controls

Derive totals, counts, and differences from the detailed match table.

Matching sequence

  1. Normalize: standardize dates, signs, currency, whitespace, and reference formats while retaining original values.
  2. Match exact IDs: require one-to-one uniqueness and flag duplicate native references.
  3. Match controlled combinations: use amount, date window, direction, and counterparty only where the rule has been approved.
  4. Score probable matches: show the supporting fields and confidence level; do not promote them silently.
  5. Queue exceptions: assign a reason, age, owner, and next action.
  6. Reconcile: calculate source totals, matched totals, open differences, and duplicate exposure.

What the dashboard should show

  • A clear reconciliation identity: source total equals matched, open, and excluded records.
  • Exception counts and values by reason, owner, and age.
  • Duplicate candidates separated from confirmed duplicates.
  • Trend lines that distinguish new exceptions from carried-forward backlog.
  • A drill-through path from every KPI to the records behind it.

Controls that make it dependable

Stable record IDs prevent rows from losing their identity when a table is sorted. A rule register explains each automated match. Manual overrides require a reason and reviewer. Summary metrics use formulas or measures over the match table, so correcting a detail record automatically updates the report.

Next iteration

The demonstration above implements the matching sequence in the browser on a small synthetic dataset. Reusable SQL matching steps, a Power Query preparation layer, and a Power BI exception-review page are not built yet. Each artifact will be checked for confidentiality before publication.

The broader lesson

Reconciliation is strongest when uncertainty becomes visible work rather than an invisible assumption.
